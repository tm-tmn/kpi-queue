# ผังเวลารอผู้ป่วยนอก · รพ.ศรีนครินทร์ (ต้นแบบ)

หน้าเว็บ 3 มิติ มุมมอง isometric ให้หัวหน้างานและผู้อำนวยการเห็นว่าผู้ป่วยนอกอยู่จุดไหน กี่คน รอนานเท่าไร เทียบกับ KPI

> **รอบนี้เป็นข้อมูลสมมติทั้งหมด** — ผู้ป่วยจำลองมามากช่วง 06:00–09:00 แพทย์เริ่มตรวจ 08:30 เปิดหน้ามาเห็นสถานการณ์เวลา 10:30

## เปิดดู

ไม่ต้อง build เปิดผ่านเว็บเซิร์ฟเวอร์ใดก็ได้ เช่น

```bash
php -S localhost:8080        # แล้วเปิด http://localhost:8080
```

ต้องต่ออินเทอร์เน็ตเพื่อโหลด three.js (r128 จาก cdnjs) และฟอนต์

ทำไฟล์เดียวไว้ส่งต่อ: `python3 tools/build_single.py dist/kpi-queue-single.html`

## สิ่งที่มีในหน้า

| ส่วน | รายละเอียด |
|---|---|
| มุมมอง 3 ระดับ | ภาพรวม รพ. (อาคารลอกจากภาพถ่ายดาวเทียม) → คลิกอาคาร → ผังภายใน → สลับชั้น |
| ผังภายใน | ผนังเตี้ยไม่มีหลังคา พื้นห้องเป็นสีตามสถานะ KPI |
| ป้ายลอย | ชื่อจุด, จำนวนคนรอ, เวลารอเฉลี่ย |
| ตัวคน | ยืนรอหน้าจุดบริการ สีตามเวลารอ เดินไปจุดถัดไปได้ทั้งข้ามชั้นและข้ามอาคาร |
| คลิกห้อง | คิวที่รอ (HN แสดง 4 ตัวท้าย ไม่มีชื่อ) + กราฟเวลารอทุก 15 นาทีเทียบเส้น KPI |
| คลิกคน | เส้นทางตั้งแต่ยื่นบัตรถึงรับยา พร้อมเวลารอแต่ละขั้น |
| แถบบน/ตาราง | ผู้รับบริการวันนี้, อยู่ใน รพ., เวลารวมเฉลี่ย, % ผ่าน KPI, จุดที่รอนานสุด + ตารางทุกจุด |
| อื่น ๆ | โหมดสว่าง/มืด, ใช้บนมือถือได้, เลื่อนเวลา/เร่งความเร็ว, ตั้งค่า KPI (เก็บในเบราว์เซอร์) |

เกณฑ์สี: เขียว ≤ 80% ของ KPI · เหลือง 80–100% · แดง เกิน KPI
"เวลารอเฉลี่ย" = ค่าเฉลี่ยของผู้ที่เริ่มรับบริการใน 60 นาทีล่าสุด (ถ้ายังไม่มีใครเริ่ม ใช้เวลาที่ผู้รอตอนนี้รอมาแล้ว)

## โครงสร้าง

```
index.html          หน้าเว็บ
css/app.css         สไตล์ (token สี light/dark)
js/data.js          ผังอาคาร, ผังภายใน, จุดบริการ, depcode, KPI ตั้งต้น   ← แก้ตรงนี้เมื่อได้ข้อมูลจริง
js/sim.js           ตัวจำลองผู้ป่วย (discrete-event, seed คงที่) + เส้นทางเดิน
js/metrics.js       คำนวณตัวชี้วัด ณ เวลา T
js/app.js           ฉาก three.js + UI
api/                PHP 8 + PDO + service layer (ยังไม่เปิดใช้ในหน้าเว็บ)
tools/build_single.py  รวมเป็นไฟล์ HTML เดียว
```

## สิ่งที่ยังเป็นการเดา (มีป้าย "เดา" บนหน้าจอ)

1. **อาคารผู้ป่วยนอกคือหลังไหน** — ตอนนี้เดาว่าเป็นกลุ่มอาคารหลังคาสีเขียวตรงกลาง, คลินิกกุมาร/สูติ อยู่ตึก สว.19, X-ray อยู่อาคาร MRI
2. **ผังภายในทุกชั้น** — วาดขึ้นเอง รอภาพผังจริงแต่ละอาคาร/ชั้น (แก้ใน `PLANS` ของ `js/data.js`)
3. **depcode ทุกจุด** — ตัวเลขสมมติ รอผล `SELECT depcode, department FROM kskdepartment` และการจับคู่ห้อง เช่น ห้องตรวจ 3 = 005
4. **KPI** — ตั้งต้น เวชระเบียน 15, ซักประวัติ 15, รอพบแพทย์ 60, X-ray 30, Lab 45, การเงิน 15, รับยา 30, รวม 180 นาที
5. สัดส่วนคลินิก, โอกาสส่ง Lab/X-ray, จำนวนช่องบริการ — สมมติ

## ต่อข้อมูลจริง (ขั้นต่อไป)

- `api/departments.php` อ่าน `kskdepartment` ได้เลยเมื่อใส่ `api/config.php`
- `api/queue.php` ส่งเส้นทางผู้ป่วยวันนี้ในรูปแบบเดียวกับ `KQ_SIM.runSim()` — SQL ยังเป็นโครง ต้องยืนยันว่าเวลาเข้า/เรียก/ออกของแต่ละจุดเก็บอยู่ตารางไหน
- API ส่งเฉพาะ HN 4 ตัวท้าย ไม่ส่งชื่อ ควรใช้ user ฐานข้อมูลแบบอ่านอย่างเดียว
- การควบคุมกล้องเขียนเองเพื่อล็อกมุม isometric และรองรับนิ้วบนมือถือ เปลี่ยนเป็น OrbitControls ได้ถ้าทีมต้องการให้ตรงกับระบบเดิม
