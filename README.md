# ผังเวลารอผู้ป่วยนอก · รพ.ศรีนครินทร์ (ต้นแบบ)

หน้าเว็บ 3 มิติ มุมมอง isometric ให้หัวหน้างานและผู้อำนวยการเห็นว่าผู้ป่วยนอกอยู่จุดไหน กี่คน รอนานเท่าไร เทียบกับ KPI

> **รอบนี้เป็นข้อมูลสมมติทั้งหมด** — ผู้ป่วยจำลองมามากช่วง 06:00–09:00 แพทย์เริ่มตรวจ 08:30 เปิดหน้ามาเห็นสถานการณ์เวลา 10:30

## เปิดดู

ไม่ต้อง build เปิดผ่านเว็บเซิร์ฟเวอร์ใดก็ได้ เช่น

```bash
php -S localhost:8080        # แล้วเปิด http://localhost:8080
```

ต้องต่ออินเทอร์เน็ตเพื่อโหลด three.js (r128 จาก cdnjs) และฟอนต์

ทำไฟล์เดียวไว้ส่งต่อ: `python3 tools/build_single.py dist/kpi-queue-single.html`

## สิ่งที่มีในหน้า

| ส่วน | รายละเอียด |
|---|---|
| มุมมอง 3 ระดับ | ภาพรวม รพ. (อาคารลอกจากภาพถ่ายดาวเทียม) → คลิกอาคาร → ผังภายใน → สลับชั้น |
| ผังภายใน | ผนังเตี้ยไม่มีหลังคา พื้นห้องเป็นสีตามสถานะ KPI |
| ป้ายลอย | ชื่อจุด, จำนวนคนรอ, เวลารอเฉลี่ย |
| ตัวคน | ยืนรอหน้าจุดบริการ สีตามเวลารอ เดินไปจุดถัดไปได้ทั้งข้ามชั้นและข้ามอาคาร |
| คลิกห้อง | คิวที่รอ (HN แสดง 4 ตัวท้าย ไม่มีชื่อ) + กราฟเวลารอทุก 15 นาทีเทียบเส้น KPI |
| คลิกคน | เส้นทางตั้งแต่ยื่นบัตรถึงรับยา พร้อมเวลารอแต่ละขั้น |
| แถบบน/ตาราง | ผู้รับบริการวันนี้, อยู่ใน รพ., เวลารวมเฉลี่ย, % ผ่าน KPI, จุดที่รอนานสุด + ตารางทุกจุด |
| อื่น ๆ | โหมดสว่าง/มืด, ใช้บนมือถือได้, เลื่อนเวลา/เร่งความเร็ว, ตั้งค่า KPI (เก็บในเบราว์เซอร์) |

เกณฑ์สี: เขียว ≤ 80% ของ KPI · เหลือง 80–100% · แดง เกิน KPI
"เวลารอเฉลี่ย" = ค่าเฉลี่ยของผู้ที่เริ่มรับบริการใน 60 นาทีล่าสุด (ถ้ายังไม่มีใครเริ่ม ใช้เวลาที่ผู้รอตอนนี้รอมาแล้ว)

## ต่อข้อมูลจริงจาก HIS (HOSxP)

หน้าเว็บตรวจเองว่ามี `api/` (PHP) หรือไม่ — ถ้ามี ใช้ข้อมูลจริงทันที ถ้าไม่มี (เช่นเปิดเป็นไฟล์เดี่ยว) ใช้ข้อมูลสมมติพร้อมป้ายกำกับ
บังคับดูข้อมูลสมมติได้ด้วย `index.html?demo=1` · เมื่อติดตั้งบนเซิร์ฟเวอร์แล้ว **จะไม่สลับไปใช้ข้อมูลสมมติเอง** ถ้าต่อ HIS ไม่ได้จะขึ้นป้ายแดงและแสดงข้อมูลรอบล่าสุด

### ติดตั้ง

1. DBA สร้าง user อ่านอย่างเดียว ตาม `sql/01_check_tables.sql` ขั้นที่ 0 (ไม่ต้องให้สิทธิ์ตาราง `patient`)
2. `cp api/config.example.php api/config.php` แล้วใส่ DSN, รหัสผ่าน, `admin_username`, `admin_password_hash`, `secret`
   (สร้าง hash: `php -r "echo password_hash('รหัสผ่าน', PASSWORD_DEFAULT), PHP_EOL;"` แล้ววางในเครื่องหมาย ' ' เดี่ยว เพราะ hash มีตัว $)
3. ให้ web server เขียนโฟลเดอร์ `storage/` ได้ (เก็บ settings และแคช) — ไฟล์ทุกไฟล์ใน storage เป็น `.php` ที่ขึ้นต้นด้วยคำสั่ง exit จึงอ่านตรง ๆ จากเว็บไม่ได้แม้ server ไม่อ่าน `.htaccess` · nginx ควรใส่ `location ~ ^/(storage|config|sql|tools|tests|api/lib|api/services)/ { deny all; }` เพิ่ม
4. เปิด `settings.html` → เข้าสู่ระบบ → **ตรวจตาราง** → เลือกตาราง/คอลัมน์ → จับคู่ห้องกับรหัสแผนก → บันทึก

### อ่านอย่างเดียว 3 ชั้น

| ชั้น | วิธี |
|---|---|
| ฐานข้อมูล | user มีสิทธิ์ `SELECT` เฉพาะตารางที่ใช้ |
| session | ต่อแล้วตั้ง `SET SESSION TRANSACTION READ ONLY` ทันที (ทดสอบแล้ว: แม้ใช้ user ที่เขียนได้ UPDATE/DELETE ก็ error) |
| โค้ด | `Database::select()` รับเฉพาะ SELECT/SHOW/WITH คำสั่งเดียว · ชื่อตาราง/คอลัมน์จากหน้าตั้งค่าผ่านการตรวจรูปแบบ และต้องมีอยู่จริงใน information_schema |

ดึงซ้ำทุก 30 วินาที (แก้ได้ในหน้าตั้งค่า) · แคชฝั่งเซิร์ฟเวอร์ 25 วินาที เปิดกี่จอฐานข้อมูลก็ถูกถามไม่เกิน 1 ครั้งต่อรอบ

### ข้อมูลที่ส่งไปหน้าจอ (`api/live.php`)

เฉพาะ: รหัสอ้างอิงรายวัน (HMAC ของ VN — ไม่ส่ง VN), เลขคิว, HN 4 ตัวท้าย (ตัดตั้งแต่ใน SQL ด้วย `RIGHT(hn,4)`), รหัสแผนก + ชื่อแผนก, เวลา (นาทีนับจาก 00:00)
ไม่มีชื่อ-นามสกุล และไม่ query ตาราง `patient` เลย · บีบอัด gzip ราว 150 KB ต่อรอบสำหรับ ~2,300 visit

### คำนวณจากคอลัมน์ไหน

ทุกจุดบริการใช้เวลา 3 ค่า ซึ่งผู้ดูแลเลือกคอลัมน์ในหน้าตั้งค่า (ชื่อคอลัมน์จริงยังรอผล SHOW COLUMNS)

| ค่า | ความหมาย | ใช้ใน |
|---|---|---|
| เข้าคิว (`a`) | มาถึงจุด/ส่งเข้าคิว | เริ่มนับเวลารอ, จำนวนคนรอ |
| เรียก (`s`) | เริ่มให้บริการ | **เวลารอ = s − a** |
| เสร็จ (`e`) | ออกจากจุด | **เวลาให้บริการ = e − s**, รับบริการแล้ว |

- เวลามา รพ. = `ovst.vsttime` (ตาราง visit) · เวลารวม = เวลารับยาเสร็จ − เวลามา เทียบ KPI รวม
- เวลารอเฉลี่ยของจุด = ค่าเฉลี่ย `s − a` ของผู้ที่ถูกเรียกใน 60 นาทีล่าสุด
- กราฟทุก 15 นาที = ค่าเฉลี่ย `s − a` จัดกลุ่มตามเวลาเรียก + จำนวนคนรอ ณ ปลายช่วง

### เมื่อบางจุดไม่ได้กดบันทึกเวลา (NULL หรือ 00:00:00)

| กรณี | การจัดการ | หน้าจอ |
|---|---|---|
| ไม่มีเวลาเข้าคิว | ใช้เวลาเสร็จของจุดก่อนหน้า (จุดแรกใช้เวลามา รพ.) | เวลามี `*` "อนุมานจากจุดก่อนหน้า" |
| ไม่มีเวลาเข้าคิวและอนุมานไม่ได้ | ไม่ทราบเวลารอ ไม่นับในค่าเฉลี่ย | `?` |
| เสร็จแล้วแต่ไม่มีเวลาเรียก | นับเป็นผู้รับบริการ แต่ไม่นับในค่าเฉลี่ยเวลารอ | "ไม่ได้บันทึกเวลาเรียก (อยู่ที่จุด ≈ N นาที)" |
| จุดที่แทบไม่บันทึกเวลาเรียกเลย (>90%) | ใช้ **เวลาอยู่ที่จุด = e − a** แทน (รวมเวลาให้บริการ) | ค่ามี `≈` และป้าย "ประมาณจากเวลาเข้า-ออก" |
| ไม่มีเวลาเสร็จ แต่ไปจุดถัดไปแล้ว | ใช้เวลาเข้าจุดถัดไปเป็นเวลาเสร็จ | `*` "ใช้เวลาเข้าจุดถัดไปแทน" |
| เข้าคิวนานเกิน 240 นาที ไม่มีเวลาเรียก/เสร็จ | "ค้างในระบบ" ไม่นับเป็นผู้รอ ไม่วาดตัวคน | แจ้งจำนวนในแผงห้อง |
| ไม่มีความเคลื่อนไหว 120 นาทีหลังจุดสุดท้าย (ไม่มีเวลารับยา) | ถือว่ากลับแล้ว | "ไม่มีความเคลื่อนไหวนานเกินเกณฑ์" |
| จุดที่ไม่มีข้อมูลเลยวันนี้ | — | ป้ายสีเทา "ยังไม่มีข้อมูลวันนี้" |
| รหัสแผนกที่ยังไม่จับคู่ห้อง | ไม่หายไปเงียบ ๆ | แถวท้ายตาราง "ยังไม่ได้จับคู่" + ลิงก์ไปหน้าตั้งค่า |

คอลัมน์ "บันทึกครบ" ในตาราง = % ของผู้ที่เสร็จจุดนั้นแล้ววันนี้ ที่มีเวลาครบทั้ง 3 ค่าโดยไม่ต้องอนุมาน

## สิ่งที่ยังเป็นการเดา

1. ชื่อคอลัมน์เวลาใน `ovst_service_time`, `service_time`, `opd_dep_queue` — ยังไม่ได้รับผล SHOW COLUMNS จึงให้เลือกในหน้าตั้งค่า ส่วนตาราง visit ตั้งต้นที่ `ovst(vn, hn, vstdate, vsttime, oqueue, main_dep)` และชื่อแผนกจาก `kskdepartment(depcode, department)`
2. อาคารผู้ป่วยนอกคือหลังไหน และผังภายในทุกชั้น — ยังวาดเอง รอภาพผังจริง
3. การจับคู่ห้องกับรหัสแผนก — ค่าตั้งต้นเป็นเลขสมมติ แก้ได้ในหน้าตั้งค่า (เมื่อบันทึกแล้วป้าย "เดา" ที่รหัสแผนกจะหายไป)
4. รองรับ MySQL/MariaDB เป็นหลัก (โค้ดเตรียม PostgreSQL ไว้แต่ยังไม่ได้ทดสอบ)
